# Project Lanes

Project Lanes は、複数のプロジェクトを一度に表示せず、レーンを切り替えて扱うための VS Code 拡張機能です。各プロジェクトをレーンとして管理し、エクスプローラー、Git、エディタタブ、ターミナルを一つの作業コンテキストとして切り替えます。

[VS Code Marketplace から Project Lanes - Fast Switching をインストール](https://marketplace.visualstudio.com/items?itemName=yukiito1999.project-lanes)できます。

## Project Lanes が解決すること

VS Code 標準のマルチルートワークスペースは、すべてのプロジェクトをエクスプローラーに並べ、タブとターミナルも一つのウィンドウに混在させます。複数のコーディングエージェントや長時間動くプロセスを別々のプロジェクトで動かすと、目的の作業を追いにくくなります。

Project Lanes はプロジェクトを一つのワークスペースに保持したまま、アクティブなレーンだけを表示します。別のレーンのターミナルはバックグラウンドで動き続け、活動状態から作業中または入力待ちのレーンを確認できます。

## 動作要件

- VS Code 1.101 以降
- シンボリックリンクを利用できる Linux または macOS
- 一つ以上のプロジェクトフォルダーを含む、保存済みの `.code-workspace` ファイル

Windows は未検証です。未保存のワークスペースは、Project Lanes で初期化する前に保存してください。

## 利用を始める

### 新しいワークスペースを作る

1. VS Code の **フォルダーをワークスペースに追加...** で、管理したいプロジェクトを追加します。
2. **名前を付けてワークスペースを保存...** で `.code-workspace` ファイルとして保存します。
3. **Lanes** ビューの **Initialize Workspace** を選ぶか、コマンドパレットから `Project Lanes: Initialize Workspace` を実行します。
4. **Lanes** ビューでレーンを選び、プロジェクトを切り替えます。

ワークスペースの保存後と初期化時に、VS Code がウィンドウを再読み込みする場合があります。ワークスペースの識別情報や先頭のワークスペースフォルダーが変わる際の動作です。この設定が必要なのは `.code-workspace` ファイルごとに一度だけです。

### 既存のワークスペースファイルを使う

管理したいプロジェクトフォルダーを含む `.code-workspace` ファイルを開き、`Project Lanes: Initialize Workspace` を実行します。既存のフォルダーがレーンとして取り込まれます。

### 起動時に自動で初期化する

`projectLanes.initializationMode` の既定値は `manual` です。明示的に初期化するまで、未管理のワークスペースを変更しません。`automatic` に設定すると、保存済みワークスペースを拡張機能の起動時に初期化します。未保存のワークスペースは、どちらの設定でも先に保存する必要があります。

## 初期化で変更するもの

初期化では次の処理を行います。

- 現在のワークスペースフォルダーをレーンとして VS Code のワークスペース状態に記録する
- `.code-workspace` ファイルの隣に `.lanes-root/<workspace-hash>/active` を作る
- 表示するワークスペースフォルダーを、アクティブレーンを指す一つのリンクに置き換える
- Project Lanes の管理中だけ、ワークスペースの既定ターミナルプロファイルとして Lane Terminal を選び、標準のターミナル **+** ボタンからアクティブレーンの実ディレクトリでシェルを開く

プロジェクトのディレクトリを移動、改名、編集、削除することはありません。レーン名の変更では表示用の管理情報だけを更新します。非アクティブレーンを除外すると、そのレーンのターミナルと実行中のプロセスを終了し、保存済みのタブ状態を破棄しますが、ディスク上のディレクトリは変更しません。ワークスペースファイルを Git リポジトリ内に保存する場合、生成ディレクトリを追跡したくなければ、そのリポジトリの `.gitignore` に `.lanes-root/` を追加してください。

## 日常の操作

### レーンを切り替える

**Lanes** ビューでレーンを選ぶか、`Project Lanes: Switch Lane` を実行します。エクスプローラーと Git が選択したプロジェクトへ切り替わり、直前のレーンのファイルタブを保存して、切替先のタブを復元します。

未保存の変更がある場合は、先にファイルを保存してください。変更を失わないよう、Project Lanes はレーン切替を中止します。

### プロジェクトを追加する

**Lanes** ビューの **+** ボタンからフォルダーを選びます。VS Code 標準の **フォルダーをワークスペースに追加...** も利用できます。管理済みワークスペースでは、追加したフォルダーをレーンに取り込み、エクスプローラーをアクティブレーンだけの表示へ戻します。ワークスペースの再保存と再初期化は不要です。

### レーンを管理する

レーンの右クリックメニューから、表示名の変更とワークスペースからの除外ができます。レーンを除外してもディスク上のディレクトリは残ります。アクティブレーンは除外できません。ディレクトリを移動した場合や読み取れなくなった場合は、`Project Lanes: Locate Folder` で読み取り可能なディレクトリに再関連付けします。

### 全レーンを検索する

`Project Lanes: Find in Lanes` は ripgrep で読み取り可能な全レーンのファイル内容を検索します。`Project Lanes: Go to File in Lanes` は読み取り可能な全レーンからファイル名で対象を探します。結果を選ぶと、そのファイルが属するレーンへ切り替えてからファイルを開きます。

## レーン切替に追従するもの

| 対象                  | 動作                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| エクスプローラー、Git | アクティブレーンだけを表示                                                                           |
| エディタタブ          | 通常のファイルタブをレーンごとに保存、復元し、VS Code の再起動後も保持                               |
| ターミナル            | 標準の **+** からアクティブレーンの実ディレクトリで Lane Terminal を開き、切替後もそのプロセスを維持 |
| 活動状態              | 活動状態表示が有効な場合は `working` または `waiting` を表示。表示がなければ `no-agent`              |

活動状態は OSC 633 シェル統合とターミナル出力を組み合わせた汎用ヒューリスティックで判定します。`bash` と `zsh` に対応し、特定のコーディングエージェントには依存しません。

## レーン切替の仕組み

ワークスペースには `.lanes-root/<workspace-hash>/active` という一つの安定したフォルダー URI を公開します。レーン切替で変更するのはシンボリックリンクの参照先だけです。拡張ホストを再起動せずに切り替えられるため、バックグラウンドのターミナルプロセスも動き続けます。

64 文字の SHA-256 ワークスペースハッシュを省略せず使い、同じディレクトリにある `.code-workspace` ファイルごとに別のアクティブリンクを割り当てます。レーンカタログの正本は `.code-workspace` ファイルではなく、VS Code のワークスペース状態です。

## コマンド

| コマンド                                   | 説明                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------ |
| `Project Lanes: Initialize Workspace`      | 保存済みワークスペースのフォルダーを取り込み、管理を開始                       |
| `Project Lanes: Switch Lane`               | レーンを切替                                                                   |
| `Project Lanes: Add Folder to Workspace`   | アクティブレーンの親からフォルダー選択を始め、レーンとして追加                 |
| `Project Lanes: Reload Lanes`              | ワークスペースフォルダー、アクティブリンク、保存済み選択を再整合               |
| `Project Lanes: Locate Folder`             | 見つからない、または読み取れないレーンを、読み取り可能なフォルダーへ再関連付け |
| `Project Lanes: Rename Lane`               | レーンの識別子とセッションを維持したまま表示名を変更                           |
| `Project Lanes: Remove Lane`               | ディレクトリを削除せず、非アクティブレーンをカタログから除外                   |
| `Project Lanes: Close Terminals`           | アクティブレーンの全ターミナルセッションを終了                                 |
| `Project Lanes: Toggle Activity Indicator` | VS Code を再起動せずに活動状態表示を切替                                       |
| `Project Lanes: Find in Lanes`             | 読み取り可能な全レーンのファイル内容を検索して一致箇所を開く                   |
| `Project Lanes: Go to File in Lanes`       | 読み取り可能な全レーンからファイルを探して開く                                 |

## 設定

| 設定                                  | 既定値   | 説明                                                         |
| ------------------------------------- | -------- | ------------------------------------------------------------ |
| `projectLanes.initializationMode`     | `manual` | 未管理の保存済みワークスペースを明示操作または起動時に初期化 |
| `projectLanes.activity.showIndicator` | `true`   | バッジ、装飾、ステータスバーにレーンの活動状態を表示         |
| `projectLanes.terminal.shellPath`     | `""`     | Lane Terminal で使うシェル。空の場合は `$SHELL` を使用       |

## v0.1.13 から更新する場合

旧版の `.lanes-root/active` は、現在のワークスペースフォルダーと保存済みカタログの両方から対象ワークスペースのものと確認できた場合だけ読み取ります。旧リンクは移行元として扱い、変更も削除もしません。

旧版がワークスペースのターミナル設定を残している場合があります。現在値と旧版の設定が一致した場合だけ、Project Lanes が扱いを確認します。

- `Manage Lane Terminal` は、一致した既定プロファイルを Project Lanes の管理下に引き継ぐ
- `Keep Current Settings` は、一致した値を維持したまま、現在のターミナルプロファイル管理を開始する
- `Remove Legacy Settings` は、一致した値を削除してから、現在のターミナルプロファイル管理を開始する

どの選択でも、Project Lanes の管理中は標準のターミナル **+** ボタンが Lane Terminal を開きます。拡張機能の終了時には、その設定を利用者や別の処理が変更していない場合だけ、以前の既定プロファイルへ戻します。

## 制約事項

- シンボリックリンクによる切替は Linux と macOS 向けです。Windows は未検証です。
- 活動状態の判定には `bash` または `zsh` と OSC 633 が必要です。`fish`、`pwsh` などでは `no-agent` にフォールバックします。
- エディタの復元対象は通常のファイルタブです。差分ビュー、ノートブックなどは対象外です。
- ターミナルセッションは VS Code ウィンドウの再読み込みをまたいで保持されません。
